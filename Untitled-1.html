Práctica: Sistema de Notificaciones

Clases abstractas, herencia y polimorfismo

Duración estimada: 45 a 60 minutos Modalidad: Individual o en parejas Herramientas: Python y UML

1. Contexto

Una aplicación requiere enviar notificaciones a sus usuarios mediante distintos canales: correo electrónico, mensaje de texto (SMS) y notificación push. Cada canal posee su propia lógica de envío; sin embargo, todos comparten características comunes.

El objetivo de la práctica es diseñar e implementar el sistema completo.

2. Requisitos

2.1. Clase abstracta Notificacion

La clase debe incluir los siguientes elementos:

  • Atributo: destinatario (nombre o identificador del usuario).
  • Atributo: mensaje (texto que se enviará).
  • Método abstracto: enviar(), implementado por cada canal según su propia lógica.
  • Método abstracto: costo(), ya que cada canal tiene un costo distinto.
  • Método concreto: resumen(), que devuelve un texto legible con la información común.
  • Propiedad calculada: tipo, que devuelve el nombre real de la clase.
  • Validaciones: el destinatario y el mensaje no pueden estar vacíos.

2.2. Subclases concretas

Se deben implementar como mínimo tres de los siguientes canales (se permite implementar los tres):

Email

  • Atributos: asunto, cuerpo, dominio (por ejemplo, "gmail.com").
  • Costo: $0.01 por envío.
  • Estado al enviar: "ENVIADO".

SMS

  • Atributos: numero_telefono, operadora.
  • Costo: $0.10 por envío.
  • Validación: el número debe contener exactamente 10 dígitos.
  • Estado al enviar: "ENTREGADO".

PushNotification

  • Atributos: dispositivo ("Android" o "iOS"), token.
  • Costo: $0.00 (gratuito, aunque requiere token).
  • Validación: el dispositivo debe ser "Android" o "iOS".
  • Estado al enviar: "RECIBIDO".

3. Entregables

3.1. Diagrama UML

Elabore el diagrama de clases, el cual debe mostrar:

  • La clase abstracta con sus atributos, métodos abstractos y métodos concretos.
  • Las subclases con sus atributos y métodos propios.
  • Las relaciones de herencia.
  • Los símbolos de visibilidad: - (privado), # (protegido) y + (público).

El diagrama puede realizarse a mano o con herramientas como draw.io, Lucidchart o similares.

3.2. Código

Implemente el sistema en Python. El código debe cumplir obligatoriamente con lo siguiente:

  • Importar from abc import ABC, abstractmethod.
  • La clase base debe heredar de ABC.
  • Los métodos obligatorios deben estar decorados con @abstractmethod.
  • Cada subclase debe invocar super().__init__().
  • Cada subclase debe implementar todos los métodos abstractos.
  • Validar los datos en el constructor, lanzando ValueError cuando sean inválidos.
  • Emplear try/except para capturar errores al crear o utilizar objetos.
  • Utilizar isinstance() en alguna parte del código para demostrar el polimorfismo.

3.3. Demostración en consola

Cree un archivo main.py que realice lo siguiente:

  1. Cree al menos una instancia de cada subclase.
  2. Almacene las instancias en una lista.
  3. Recorra la lista con un ciclo for e invoque resumen(), enviar() y costo() de cada objeto.
  4. Intente instanciar Notificacion directamente (la operación debe fallar).
  5. Defina una subclase incompleta (sin implementar enviar()) e intente instanciarla (la operación debe fallar).
  6. Muestre el MRO de cada subclase mediante Clase.__mro__.
  7. Emplee isinstance() para verificar que todas las instancias pertenecen también a Notificacion.

4. Restricciones

Consideraciones obligatorias
  • No se permite utilizar NotImplementedError como sustituto de @abstractmethod.
  • No se debe repetir en las subclases la lógica que ya esté definida en la clase base.
  • No se deben incluir en la clase base métodos que apliquen únicamente a una subclase.
  • Se permite añadir métodos propios que solo posean algunas subclases.
  • Se permite añadir propiedades y validaciones adicionales cuando se consideren pertinentes.

5. Preguntas de reflexión

Además del código, responda brevemente las siguientes preguntas:

  1. ¿Por qué Notificacion es una clase abstracta y no una clase ordinaria?
  2. ¿Qué diferencia existe entre enviar() y resumen() en cuanto a su naturaleza (abstracto o concreto)? Justifique la decisión adoptada.
  3. ¿Qué ocurre si se omite la implementación de costo() en una subclase? ¿En qué momento se detecta el error?
  4. ¿Por qué los atributos destinatario y mensaje se definen en la clase base y no en cada subclase?
  5. ¿Qué ventaja ofrece almacenar todos los canales en una misma lista y recorrerla con un ciclo for?
  6. Si se desea incorporar un nuevo canal WhatsApp, ¿qué elementos del código existente sería necesario modificar?

7. Actividad complementaria (+10 puntos)

Puntos adicionales

Añada una segunda clase abstracta, Programable(ABC), con los siguientes elementos:

  • Método abstracto programar(fecha_hora).
  • Método concreto esta_programada().

Las clases Email y PushNotification deben heredar también de Programable (herencia múltiple). La clase SMS no debe heredar de ella, dado que los mensajes de texto no se programan.

Investigue y responda:

  • ¿Cuál es el MRO de Email tras este cambio?
  • ¿Es posible instanciar Email si no se implementa programar()?
